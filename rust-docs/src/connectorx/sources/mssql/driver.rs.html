1//! Internal MSSQL driver seam.
2//!
3//! ConnectorX currently talks to SQL Server exclusively through `tiberius` +
4//! `bb8-tiberius`. This module introduces the seam that a future `mssql-tds`
5//! backend will plug into (see the phased migration plan tracked against
6//! sfu-db/connector-x#942), without changing any observable behavior today.
7//!
8//! Phase 0 (this change): define [`MsSQLDriverKind`] and wire an
9//! [`active_driver`] accessor into the existing Tiberius path. Only
10//! [`MsSQLDriverKind::Tiberius`] exists, so behavior is unchanged.
11//!
12//! Phase 2 will add an `mssql-tds`-backed implementation behind an opt-in
13//! Cargo feature and extend this module with the actual connection/query
14//! trait boundary once the second implementation's real shape is known.
15//! Designing that trait now, against a single implementation with the
16//! existing self-referential `OwningHandle`-based row iterator, would risk
17//! locking in the wrong abstraction before `mssql-tds`'s row/result-set API
18//! is exercised for real.
19
20/// Which MSSQL wire-protocol driver ConnectorX uses for a given source.
21///
22/// Only `Tiberius` is implemented today. `MssqlTds` is reserved for Phase 2
23/// and intentionally not constructible yet.
24#[derive(Copy, Clone, Eq, PartialEq, Debug)]
25pub(crate) enum MsSQLDriverKind {
26    /// The current, sole implementation: `tiberius` + `bb8-tiberius`.
27    Tiberius,
28}
29
30/// Returns the MSSQL driver ConnectorX will use.
31///
32/// Always returns [`MsSQLDriverKind::Tiberius`] until Phase 2 lands a second
33/// implementation and Phase 3 makes the choice configurable.
34pub(crate) fn active_driver() -> MsSQLDriverKind {
35    MsSQLDriverKind::Tiberius
36}
